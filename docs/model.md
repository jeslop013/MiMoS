# MiMoS — model description

What the model does. The model was introduced in the PhD thesis cited in the README (Chapter 7, "Micro-Mobility Model & Simulator (MiMoS)", and its pseudocode appendix); this version extends it. The input files: [input_format.md](input_format.md). Plans: [roadmap.md](roadmap.md).

## Overview

MiMoS is an agent-based transport model inspired by MATSim's co-evolutionary cycle, built from scratch. A C++17 core runs the iterations; a Python package configures runs and analyses their results.

**Input**
- A synthetic population with a daily **agenda** per agent: activity locations (lat/lon), start, end and duration times, tags, and priorities (for example work > errands > leisure > home). Demand is not generated by the model: it comes from the population data.
- Three networks, all as CSV adjacency lists where row = node id:
  - **drive** (e.g. from OSM): times, lengths, lanes, storage capacity = lanes·L/4.5 m, priority by road class, speed;
  - **bike**: lengths, times, cycleway flag;
  - **public**: urban and regional buses, trains, rental bikes. Stops are nodes; edges are itinerary links plus walking transfers between itineraries. Per-stop schedules and vehicle ids give the timetable.
- Precomputed access (source) and egress (target) candidates for each trip: for public transport the nearest stop of every itinerary; for bike and drive the nearest network nodes.

**The iteration**
1. **Routing**: for every agent, mode and trip, a Dijkstra-like search that *maximises a linear utility*:
   `U = Σ_type [C + β_t·t_trav + β_w·t_wait + β_m·Δm + (β_d + β_m·γ_d)·d]`.
   It is time-dependent for public transport (waiting for the next scheduled vehicle). Paths worse than the best one found so far, or worse than walking straight there, are pruned. An agent replans a mode only if it simulated that mode in the previous iteration (that is when new information arrives).
2. **Mode choice**: multinomial logit `P(m) ∝ exp(μ·U_m)` in iteration 0, then MCMC `min(1, exp(μ·(U_new − U_old)))`. Car and bike ownership constrain the choice.
3. **Simulation** (discrete-event, with priority queues):
   - **Public**: the interaction is vehicle occupancy. Boarding at a stop is first-in-first-out (a "ticket" number is the queue tie-breaker); unloading happens before boarding at equal times. Agents walk on to their next itinerary or destination if they miss the last vehicle.
   - **Drive**: a queue-type micro-simulation. Each link has a **mouth** (gaps = lanes, re-opened t_s = 3 s after each entry: flow capacity) and **space** (storage capacity). Intersections are resolved by **road-hierarchy priority**: a car gives way if more higher-priority cars arrive within t_s than there are free gaps. Event types: agent leaves a location; agent enters the network; gap opening; check-me (car reaches the end of its link); de-saturation (a full link frees a space). Options: first-in-first-out at the link exit (`fifo_link_exit`) and a stuck-time rule (`stuck_time`) that resolves gridlocks inside the simulation. Without the stuck-time rule, cars still in link queues at the end are **gridlocked** and receive a `jam_penalty`.
   - **Bike**: no interaction; the planned route is the executed route.
4. **Memory**: short memory = delays per agent, trip and link (drive) or stop (public) in this iteration. Long memory = exponential moving average with annealed learning rate α_ℓ(k) and forgetting rate α_f(k). Long memory adds delay disutility in the next routing pass.
5. Repeat until a stochastic user equilibrium.

**Output**: planned and executed paths, passage times and scores per mode; per-trip results (`trips.csv`), a per-iteration summary (`iterations.csv`) and every road-link traversal (`drive_links.npz`). Post-processing: hot exhaust emissions (EMEP/EEA factors, split into moving and stopped time) per link and hour, an HTML report and videos.

**Sample scaling**: a run can simulate a sample of the population; `capacity_scale` then scales road storage, road flow and vehicle capacity, as MATSim does.

**Thesis version**: `legacy_mode = true` reproduces the model version used in the thesis; the default is the current version.

## Design

- Data-driven demand (agenda from the synthetic population): no demand generation step.
- Multimodal public network with **per-vehicle occupancy** and first-in-first-out boarding.
- **Generalised-utility** routing (time, waiting, money, transfers, distance) with time-dependent schedules, many access and egress candidates, and walking as the pruning bound.
- Drive simulation that separates **flow capacity (gaps / t_s)** from **storage capacity**, and resolves intersections with **road hierarchy**.
- Incremental replanning (only agents with new information) and MCMC inertia in the mode choice.
- The core needs only the C++ standard library (OpenMP optional); routing runs agents in parallel, and results do not depend on the number of threads.
